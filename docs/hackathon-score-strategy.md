## Product decision

The security boundary earns points only when it removes user work while retaining visible control.
The intended interaction is therefore:

1. the user defines chain, calls, tokens, caps, frequency, expiry, and revoke rights;
2. the user grants that mandate once;
3. the agent acts autonomously inside the exact mandate without another wallet signature;
4. stale evidence, simulation failure, policy mismatch, duplicate intent, or exhausted limits block
   automatically without requesting wider permission;
5. only scope expansion, expiry, or revoked authority requires a new owner grant.

The internal benchmark/release ceremonies are not the product journey. /session-control is the
owner-facing session entry point; /mission-control is the read-only authority and receipt surface;
/operator-ceremony is retained as a non-indexed internal evidence tool.

## Changes made to remove avoidable deductions

- Replaced stale public copy that said BSC identity was pending or absent.
- Shows finalized registration receipts and paid-hire counts without promoting them to performance.
- Replaced the primary operator-ceremony route with a one-grant Session Control entry point.
- Shows the verified grant → execute → revoke receipt chain and final authority absence in Mission
  Control.
- Added a pure mandate evaluator that distinguishes authorized-without-new-signature, blocked, and
  requires-new-grant.
- Kept the PTA amount-0 Altana effect, owner-executed first-LP state, and still-missing LP economics
  explicit.
- Added the repository license file declared by package.json.

## Highest-value next actions

1. Publish this exact release and retain the independent exact-build probe.
2. Record a short clean-room journey: discover → inspect identity/evidence → define mandate → grant
   once → observe receipt/revoke → inspect Proof Room.
3. Freeze submission copy and retain the authoritative entry receipt.
4. Only if separately authorized and economically safe, close Pancake with a controlled minimal
   liquidity action plus before/after benefit net of gas, slippage, fees, and impermanent loss.
5. Add a public hire path only when its payment, task completion, and failure/refund semantics are
   fully implemented; do not present the retained paid-hire collector as that UX.

Items 1–3 require external publication/recording/submission state and are not created by a source
commit. Item 4 requires a new exact transaction authorization. Item 5 is a separate product feature,
not a copy change.

## Explicit non-goals for this release

- No new wallet transaction, liquidity, token approval, token transfer, mainnet action, or paid
  service.
- No claim that a paid hire completed a task.
- No claim that the PTA zero approval or pool initializer delivered Pancake economic benefit.
- No claim that internal multi-agent review is external, cryptographically identified, or
  independent in an organizational sense.
- No container claim for the device-bound passkey/DPAPI worker; host-bound custody must not be
  disguised as portable deployment.
